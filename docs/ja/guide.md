# HodoCode 利用ガイド

[README](../../README.md) · [English](../en/guide.md) · [構文解説カタログ](syntax-help.md)

## 起動と解析範囲

HodoCodeはGoリポジトリの依存関係図、関数呼び出し図、根拠付きの短い解説を作るCLIと全画面TUIです。ローカルとGitHubに対応します。複数Goモジュールを扱えます。外部Go依存はありません。Go 1.23以上が必要です。

```sh
go build -o hodocode ./cmd/hodocode
./hodocode --help
```

`--root` は解析するリポジトリまたはモジュールのディレクトリです。既定はカレントディレクトリです。配下の `go.mod` をすべて検出します。直下に `go.mod` がなくても構いません。全体を見る場合はリポジトリのルートを指定します。解析と図示にはネットワークもfxも不要です。リダイレクトで既存ファイルを上書きしないよう、出力先を確認してください。

## CLIで図と関数を見る

```sh
./hodocode deps --root /path/to/repo --dir internal --depth 1
./hodocode deps --root /path/to/repo > imports.mmd
./hodocode functions --root /path/to/repo
./hodocode flow --root /path/to/repo --func main
./hodocode flow --root /path/to/repo --func main --expand Run --expand Worker.Step
./hodocode tui --root /path/to/repo --func main
```

- `deps` は「ファイル → import先パッケージ」のMermaid図を標準出力に出します。
- `--depth` は `--dir` からのソースディレクトリの深さです。importをたどる回数ではありません。`0` は直下、`1` は1階層下まで、`-1` は全階層です。図の対象外でも、宣言は `--root` 配下のモジュール全体から索引化します。
- `functions` は関数ID、相対パス、実ファイルの行番号を表示します。
- `--func` は完全な関数ID、または一意な末尾名です。曖昧なら候補をエラーで示します。
- 直接の呼び出し先は、ルート配下の全モジュール・全パッケージの宣言から解決します。別ディレクトリや入れ子のモジュールの関数も選択できます。本体は選択したときだけ解析します。
- `--expand` は到達済みの関数を指定順に1階層ずつ展開します。全呼び出し先を一括で再帰解析しません。
- `flow` は呼び出し関係図です。ifやloopの制御フロー図ではありません。通常の矢印は静的に特定した呼び出し、破線は動的・未解決の呼び出しです。
- ルート配下とローカル標準ライブラリの関数は展開できます。他の外部依存は図示できても展開できません。import依存と呼び出し依存は別コマンド・別図です。MermaidはMarkdownの `mermaid` コードブロックに貼って編集できます。

## 全画面TUI

`--func` を省略すると、一意な `package main` の `main` から始めます。不在・複数なら理由や候補を示し、`--func` の指定を求めます。起点選択の一覧ペインはありません。

左の約3分の2に現在の関数、右の約3分の1にカーソル位置の解説を表示します。右ペインはGo構文、演算子、識別子、リテラルを具体例付きで説明します。空白上では同じ行の近いトークンを選びます。トークン、分類、位置、意味、書き方、例、注意点、公式参照を分けます。長い説明は折り返します。

解説はローカル解析と内蔵データによる日本語の定型説明です。[Go言語仕様](https://go.dev/ref/spec)を主資料とし、閲覧時に公式サイトへ接続しません。同じ `*` や `<-` も用途を区別します。ループ、関数、配列・スライス、組み込み関数、事前宣言型も細分化します。既知の `println`、`len`、`string` なども説明します。標準ライブラリと確認できた `fmt.Println`、`errors.Is` など38関数には専用解説があります。別名importに対応し、独自の同名関数を名前だけで標準関数扱いしません。判定範囲と編集方針は[構文解説カタログ](syntax-help.md)を参照してください。

コードには相対パス、行範囲、実ファイルの行番号を付けます。元の表記を保ち、タブは表示上だけ展開します。制御文字を端末操作として解釈しません。キーワード、文字列・ルーン、数値、コメントを色分けします。型による色分けはありません。呼び出し名だけを控えめなシアンにし、メソッドではレシーバーを含めません。引数、括弧、コメントにマーカーは付けません。

上部はファイル位置と右ペインの状態を示します。下部はモード、コード位置、解説スクロール位置を示します。操作案内は端末幅と生成状況に合わせて変わります。追加指示欄は中央の独立したパネルです。

### キー操作

| キー | 操作 |
| --- | --- |
| `h/j/k/l`、矢印 | コードを1文字・1行ずつ移動 |
| `w` / `B` | 次・前の単語 |
| `0` / `$` | 行頭・行末 |
| `g`（`gg` も可）/ `G` | 関数の先頭・末尾 |
| `PageUp` / `PageDown` | 1画面ずつ移動 |
| `n` / `N` | 出現順に次・前の呼び出し箇所 |
| `Enter` | カーソル上の解決済み呼び出し先へ進む |
| `b` | 直前の呼び出し元へ戻る |
| `[` / `]` | 右ペインを上下スクロール |
| `{` / `}` | 変数ポップアップだけを上下スクロール |
| `t` | 呼び出しツリーを開く |
| `v` / `r` | Neovimで開く / 明示的に再解析 |
| `e` / `s` | エージェント画面 / ローカル構文解説 |
| `i` / `E` | エージェント画面で追加指示入力 / 即時生成 |
| `c` | 生成済み行解説の表示・非表示 |
| `q`、`Ctrl+C`、`Ctrl+D` | 終了（入力中やポップアップでは下記の例外あり） |

Vim風の閲覧専用操作です。編集機能はありません。`Tab` のペイン切替と `d` の詳細切替もありません。長いコード行は折り返しません。カーソルは縦横に追従します。選択中の呼び出し名は青背景・白太字です。同じ関数への複数の呼び出しも個別に選べます。`b` はカーソル、選択、スクロール位置を復元します。

外部・未解決の呼び出しも選べます。黄色系の文字と下線で区別し、ソース不足や静的特定不能などの理由を示します。移動不能な箇所や呼び出し名以外で `Enter` を押しても移動しません。ステータスに選択番号とソース位置を示します。再帰先・解析済み関数はキャッシュを使い、再解析しません。`NO_COLOR` でコード、ヘッダー、入力欄を含む色装飾を省きます。

### 呼び出しツリー

`t` は中央のポップアップを開きます。起点は移動履歴の最初の関数です。履歴がなければ現在の関数です。現在の関数への経路と直接の子を最初に表示します。

- `j/k`・上下矢印は選択だけを動かします。`Space` で枝を展開・折り畳みます。展開時に段階的に解析し、別の枝を選んでも開閉状態を保ちます。
- `Enter` でコードへ移動します。`b` で移動前へ戻れます。
- `Esc`・`q`・`t` はポップアップだけを閉じ、コード・解説の表示位置を保ちます。`Ctrl+C/D` は終了します。
- 下部に完全な関数ID、相対パス、行番号を示します。循環参照はそれ以上展開しません。同じ親の同じ呼び出し先はまとめます。外部・未解決項目は理由付きで残し、移動・展開しません。
- 縦スクロール、リサイズ、`NO_COLOR` に対応します。

### 宣言と変数を読む

struct型名ではフィールドを含むtype宣言を表示します。スライス変数では宣言・初期化を表示します。要素が名前付きstruct型なら、その定義も併記します。スコープと型情報を使い、プロジェクト、ローカルSDK、手元の外部依存ソースを検索します。

標準ライブラリは関数・メソッドの本体、型、定数、変数、フィールドの宣言を表示できます。関数・メソッドへの `Enter` 移動とツリー展開もできます。他の外部依存はstruct・スライスの右ペイン表示と変数ポップアップだけです。移動・展開はしません。

変数名にカーソルを置くと、表示中の関数内で同じ変数の宣言・参照を同色で強調します。宣言コードとファイル・行番号はカーソル上下のポップアップに表示します。型解析で同名の別変数やクロージャーを区別します。引数、レシーバー、名前付き戻り値、range変数にも対応します。変数以外へ移動すると解除します。未解決の識別子は推測で強調せず、取得できない旨を示します。

表示元はプロジェクト相対パス、`GOROOT/src/...`、モジュール名・選択バージョン、`vendor`、置換先を区別します。実ファイルの行番号を付けます。対象外・特定不能なら理由と構文解説を示します。ソーススナップショットだけを使い、実行時の値を取得・推測しません。外部送信もしません。エージェント会話を表示中は上書きせず、`s` でローカル表示へ戻ります。

外部依存の表示用解決では、参照元モジュール、有効な `go.work`、`replace`、`vendor`、ローカルモジュールキャッシュに従います。必要なパッケージだけを遅延解析し、プロセス内で再利用します。SDKは実行環境の `GOROOT` と解析時のOS・CPU・ビルド条件を使います。ローカルGoコマンドから読み取り専用メタデータを取得します。ネット接続、依存・ツールチェーン取得、依存設定の更新、ビルド、テスト、コード生成は行いません。Goコマンドやソースがなければ理由と構文解説に戻ります。不足する依存は別途取得してください。追加ソースはローカル表示専用です。`functions` とAI送信の対象はプロジェクト内の関数だけです。

### 端末と代替表示

全画面表示はmacOS/Linuxの端末向けです。リサイズでも関数と選択を保ちます。41列×8行未満なら拡大を案内します。通常終了、`Ctrl+C`、エラー時に端末の入力設定と画面を復元します。

入出力いずれかのリダイレクト、`TERM=dumb`、他のOSでは行入力表示を使います。ツリー下のコードを番号で選び、`b` で戻り、`q` またはEOFで終了します。起点選択も従来の行入力方式です。行入力表示はAI送信をしません。マウス操作はしません（AIコメントのクリック操作は下記参照）。図は `deps` と `flow` で出力します。

## Neovim連携

通常モードの `v` は現在のソースを同じ行・列で `nvim` に開きます。終了後は閲覧位置と履歴を保ってTUIへ戻ります。未インストールや起動失敗でも理由を示し、閲覧を続けます。検索中、検索文字列・エージェント指示の入力中、ツリー表示中は起動しません。GitHubから取得したリモートソースでは編集できません。編集する場合はローカルクローンを `--root` で指定します。

保存後は `r` で再解析します。自動更新はしません。失敗時は元の表示を保ちます。現在の関数が削除されたら、残った履歴の関数、main、または残存関数へ移り、復帰先を示します。再解析は生成を中断し、検索状態をリセットします。会話履歴は保持しますが、過去の回答は生成時のソースに基づきます。行解説は対象関数のソース・ファイル・行範囲が同じなら保持します。変わったら非表示にし、`E` での再生成を案内します。

既存のNeovimを使う場合:

```sh
nvim --listen /tmp/hodocode-nvim
./hodocode tui --root /path/to/repo --nvim-server /tmp/hodocode-nvim
```

明示した接続先にだけファイルと位置を送ります。自動接続や、接続失敗時の別インスタンス起動はしません。HodoCodeの閲覧は続くため、編集は接続先のNeovim端末へ切り替えてください。ファイルは絶対パスの引数で渡します。サーバー接続時はエスケープした式を使います。シェルは介しません。

## GitHubリポジトリ

```sh
./hodocode functions --repo https://github.com/owner/repo --ref main
./hodocode flow --repo https://github.com/owner/repo --ref v1.0.0 --func main
./hodocode deps --repo https://github.com/owner/repo --subdir services/api
./hodocode tui --repo https://github.com/owner/repo
./hodocode explain --repo https://github.com/owner/repo --func main --purpose '役割を確認'
```

- `--repo` と `--root` は併用できません。対象言語はGoのみです。対象またはリポジトリ内の親に `go.mod` が必要です。複数モジュールにも対応します。
- `--ref` はブランチ、タグ、コミットです。既定は既定ブランチです。毎回GitHubでSHAに解決し、結果に表示します。再現時はそのSHAを指定します。関数一覧、呼び出し図、解説プレビュー、TUIにはSHAと行番号付きの固定ソースURLも表示します。
- `--subdir` は解析範囲だけを限定します。親モジュールは引き継ぎますが、範囲外は索引化しません。リポジトリ外のパスは拒否します。取得容量を減らす設定ではありません。
- GitHub APIとソースアーカイブを使います。Git、ビルド、スクリプト、Gitフックは実行しません。依存を自動取得しません。アーカイブのリンクや危険なパスは拒否します。
- `--fetch-timeout` の既定は `2m` です。`--max-bytes` の既定は `104857600`（100 MiB）です。取得時間と圧縮・展開サイズを制限します。`Ctrl+C` で中断できます。取得失敗時の一時データは削除します。
- ソースはOSのユーザーキャッシュ下の `hodocode/repositories` に、リポジトリ・SHA単位で保存します。保存先は `--cache-dir PATH`、再取得は `--refresh` です。削除は `hodocode cache --repo URL --delete [--cache-dir PATH]` です。キャッシュ利用時もSHA解決の通信は必要です。
- 非公開リポジトリは `--private` を明示し、事前に `gh auth login` で認証します。既存のgh認証は取得時だけ使い、ログやAI送信には含めません。非公開ソースもキャッシュに残ります。不要なら削除してください。
- 取得と静的解析だけではAIへ送信しません。`explain` は既定でローカルプレビューです。`--exclude` も適用します。送信は `--send` または全画面TUIでの明示操作だけです。

## AI解説と送信操作

インストール・認証済みのfxが必要です。モデル、送信先、料金はfxの設定に従います。回答の正確さは保証しません。出典を確認してください。

### CLIでプレビューして送信する

```sh
./hodocode explain --root /path/to/repo --func Run \
  --purpose '役割と処理の流れを知りたい' \
  --exclude 'internal/auth' --exclude '*_generated.go'
```

これは送信候補一覧のローカル確認です。fxを起動しません。目的、候補ファイル、コード、fx設定を確認してから、同じ指定に `--send --timeout 2m` を付けます。

通信は2回です。

1. 目的、許可された関数メタデータ、起点の1階層分の呼び出し関係を送り、最大12個の関数IDを選ばせます。
2. 選択を許可一覧と照合します。該当関数の加工済みコード、位置、関係だけを送り、日本語で役割・流れ・注意点を短く説明させます。ファイル・行番号を根拠とし、事実と推論を分けるよう指示します。

不正なID・JSON、重複、過大入力はエラーです。任意のパスやコマンドとして解釈しません。接続は `internal/explain.Runner` に分離され、解析を変えずに置き換えられます。

### TUIでの生成と会話

`tui` も `--purpose`、`--exclude`、`--timeout` を使えます。既定の目的は初心者向けの役割・流れ・構文・注意点です。既定タイムアウトは2分です。CLIと同じ除外、空白化、サイズ検査を適用します。TUIが確認を省略してもfxの権限設定は変わりません。CLIの `explain --send` の動作も変わりません。

- `e` は会話画面の表示だけです。入力や送信は始めません。再度押しても会話を保ちます。生成中も表示を切り替えられ、進行状況を示します。
- `i` は会話画面の右ペイン下部に常設された入力欄へ移ります。開いた時点の対象関数に紐づきます。開くだけでは送信しません。日本語入力、左右キーで移動、`Backspace` / `Delete` で削除、`Home` / `End`（`Ctrl+A/E`）で行頭・行末へ移動、`Ctrl+U/K` でカーソル前後の行内消去、`Esc` で取消に対応します。`Alt+Enter` または `Ctrl+J` は改行です。`q` は文字です。`Ctrl+C/D` は終了します。
- 入力欄の `Enter` は直ちに送信します。`y/n` 確認はありません。質問は最大8KiBです。目的とは別に、過去の質問・回答と対象関数IDも送ります。質問・回答の機密情報にも注意してください。
- `E` は入力欄なしで現在の関数の解説を直ちに生成します。回答済みでも会話へ追記し、過去の回答は上書きしません。
- 同時生成は1件です。生成中の `i`・`E` は新しい処理を始めません。`x` でアプリを終了せず生成だけを中断できます。失敗後は `i` で再入力、または `E` で再生成できます。
- 追加質問には尋ねた点だけを回答させます。全体改訂は明示依頼時だけです。通常の質問では行コメントを変えません。`/comments 修正内容` または `E` の成功時だけ置き換えます。失敗時は古いコメントを保ちます。

概要は右ペイン、行単位の詳細は左の対象コード直下に表示します。「AI解説」は専用色の仮想コメントです。ソースや元の行番号を変えません。長文は左幅で折り返し、複数行の説明は末尾行の下に置きます。ファイル・関数・行範囲を検証できない説明は右に表示します。`c` は行解説を一括表示・非表示にするだけです。再生成・送信はしません。右の `e/s` 切替とは独立です。コメントのクリックは対応コード行を選択します。移動、検索、呼び出し先移動、Neovimは元のコード位置を使います。

生成中もコード移動できます。結果は開始時の関数に紐づき、移動先には挿入しません。元へ戻ると行解説を表示します。終了時は生成を中断します。概要やエラーは右に表示し、`[` / `]` でスクロールします。

会話は発言者・対象関数ID付きで時系列に追記します。起動中の1セッションで共有し、関数移動後も文脈を保ちます。通常は会話末尾を追従します。`[` / `]` または右ペインのホイールで過去の会話を読んでいる間は表示位置を保ち、新着を知らせます。`f` で末尾へ戻り追従を再開します。`<` / `>` で右ペインの幅を調整できます。対象関数IDは対象が変わったときだけ表示し、入力欄では送信対象を常に確認できます。進行状況・エラーは本文と分離し、取消や通信失敗でも過去の回答を消しません。`s` は表示切替だけです。会話履歴と、構文・会話それぞれのスクロール位置を保ちます。終了すると履歴は失われます。ディスクには保存しません。

### 行ごとの質問

- コードのカーソル行で `a` を押すと、相対パス・実ファイルの行番号・コードを確認して質問を入力できます。`Enter` は下書き保存だけで送信しません。`?` は「これは何？」を下書きに追加します。
- `C` で行質問の一覧を開閉します。`j/k` または上下キーで項目移動、`Space` で送信対象の切替、`i` で編集、`d` で削除、`Enter` で選択分をまとめて送信します。`[` / `]` で一覧本文をスクロールできます。送信中の質問は編集・削除できません。
- 質問と回答は「行質問」の仮想コメントとして元の行の下に表示します。既存の「AI解説」は置き換えず、ソースファイルも変更しません。`c` は従来のAI行解説だけを切り替えます。
- 失敗・タイムアウト・再読み込みによる中断でも下書きを残します。一覧の `Enter` で再送できます。回答済みの質問は送信対象から外れます。再度送る場合は `Space` で選択してください。
- 再解析で対象関数のソースや位置が変わった場合、古い行への表示と送信を止めます。`C` で一覧を閉じ、対象コード行を選んでから再び一覧を開き、該当質問で `p` を押して位置を再指定してください。
- 初期対象はプロジェクト内関数です。SDK・外部依存には対象外の理由を表示し、除外されたコードは送信準備時に止めます。送信には質問ID・関数ID・相対パス・実ファイルの行番号・質問文と、既存の除外・空白化・サイズ制限を通した関数コードを含めます。質問文自体は空白化されません。
- 下書きと回答は起動中だけ保持し、終了すると失われます。

### 送信前の安全確認

- 候補には現在の関数以外の、除外されていないリポジトリ内関数も含みます。送信前に候補ファイルを監査してください。
- `--exclude` は相対パスの `filepath.Match` パターンです。ファイルと各ディレクトリ接頭パスに適用します。再帰globの `**` ではありません。除外ファイルの関数メタデータと関連ローカル辺も送りません。
- `secret`、`credential`、`token`、`key`、`private`、`.env` などを含むパス要素を自動除外します。無害なファイルも除外され得ます。
- 文字列・ルーンリテラルとコメントはすべて空白化します。実ファイルの行番号は保ちます。文字列の意味は解説できません。
- 除外・空白化は機密の完全検出を保証しません。識別子、数値、ファイル名、モジュール名、目的文にも機密があり得ます。プレビューは候補一覧で、加工後コード全体ではありません。必要な除外を指定し、準備中はファイルを変えないでください。
- fxは空の一時ディレクトリで `fx ask --no-save --no-color` として起動します。ツール・ファイル・ネットワークでの追加取得を禁じる指示を渡します。ただしOSサンドボックスではありません。fxや設定を信頼できない場合、または厳密な隔離が必要な機密リポジトリでは送信しないでください。
- 上限は1ファイル4MiB、加工後の全体8MiB、各プロンプト128KiBです。会話履歴と選択され得る最大12関数のコードも送信前に保守的に検査します。超過時は履歴やコードを黙って削らず、理由付きで送信を止めます。

## 解析の制限と評価

以下はプロジェクトの解析・索引範囲です。ローカルSDK・外部依存の表示用解決とは異なります。

- `--root` 内の `go.mod` がある領域だけを解析します。隠しファイル・ディレクトリ、`vendor`、`_test.go`、シンボリックリンクのソース、モジュール外のGoファイルは対象外です。
- プロジェクト解析では `go.work` や `require/replace` のバージョン・解決順序を再現しません。モジュール名と実在ディレクトリで解決します。異なるモジュール名への置換は未対応です。リポジトリ外の置換先や外部依存は解析対象に読み込みません。同じモジュール名・パッケージパスが複数あれば推測せずエラーにします。
- OS・CPU別ファイルとビルド制約は解析CLIの `go/build.Default` で選別します。独自ビルドタグ指定はできません。対象ファイル内に同名の複数宣言があればエラーです。
- 索引作成には対象Goファイルの構文解析が必要です。本体の型解析と呼び出し展開は選択した関数だけです。
- interface経由、関数値、型情報不足の呼び出しは不明とします。具体型のメソッドは静的に特定できれば解決します。標準ライブラリ以外の依存を取得しません。クロージャ本体へは展開しません。

```sh
go test ./cmd/hodocode ./internal/analyze ./internal/explain
go run ./cmd/hodocode flow --root testdata/analyze --func CycleA --expand CycleB
go run ./cmd/hodocode tui --root testdata/analyze --func Recur
```

`testdata/analyze` はimport、分岐内呼び出し、循環参照、動的呼び出しのサンプルです。意図的な未解決シンボルがあり、実行用ではありません。テストは外部モデルを使いません。偽fxと固定応答で送信範囲とエラー処理を検証します。
